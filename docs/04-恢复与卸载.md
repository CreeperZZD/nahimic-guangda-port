# 04 · 恢复与卸载

> ⚠️ **顺序很重要：先卸载驱动，再关测试签名。** 反过来的话，下次启动可能因签名校验失败进不了系统。

---

## 一、标准卸载流程

```powershell
# 管理员 PowerShell
.\scripts\uninstall.ps1
```

脚本依次做 7 件事：

| 步骤 | 操作 |
|---|---|
| 1 | 停止并删除 `NahimicService`，结束 `NahimicSvc32/64`、`NhNotifSys` 进程 |
| 2 | `pnputil /delete-driver ... /uninstall /force` 卸载 A-Volute 的驱动包 |
| 3 | 删除 `HKLM\SOFTWARE\Nahimic` |
| 4 | `Remove-AppxPackage` 卸载 Nahimic UWP 应用 |
| 5 | 清理音频端点上的 Nahimic 归属属性与 APO 键 |
| 6 | `bcdedit /set testsigning off`（除非指定 `-KeepTestsigning`） |
| 7 | 提示重启 |

全部执行完后**重启电脑**。

验证：

```powershell
# 应该都没有输出
Get-Service NahimicService -ErrorAction SilentlyContinue
Get-AppxPackage -Name '*Nahimic*'
Test-Path 'HKLM:\SOFTWARE\Nahimic'

# 设备管理器 -> 软件组件 -> 不应再有 A-Volute 组件
```

## 二、只回退一部分

### 只想关掉测试签名（保留音效）

**不行。** 关掉测试签名后，改签名的 EXT 驱动会在下次启动时被拒绝，音效随之失效。

如果你能接受"驱动失效但残留文件还在"，那可以：

```powershell
bcdedit /set testsigning off
```

但下次启动可能出现「系统无法验证此文件的数字签名」的启动中断，需要进恢复模式处理。**不建议走这条路。**

### 只想卸载应用，保留驱动

```powershell
Get-AppxPackage -Name '*Nahimic*' | Remove-AppxPackage
```

驱动还在，APO 还会处理音频（但没人控制它，效果固定）。

### 只想清理注册表残留

```powershell
Remove-Item 'HKLM:\SOFTWARE\Nahimic' -Recurse -Force
Stop-Service Audiosrv -Force; Start-Service Audiosrv
```

## 三、卸载后仍有残留？

### 服务删不掉

```powershell
sc.exe query NahimicService
sc.exe delete NahimicService
```

如果报「标记为删除」：

```powershell
# 重启后自动消失
Restart-Computer
```

### 驱动包删不掉

```powershell
# 列出所有 A-Volute 驱动包
pnputil /enum-drivers | Select-String -Pattern "a-volute" -Context 3,3

# 找到 Published Name（形如 oem42.inf），逐个删
pnputil /delete-driver oem42.inf /uninstall /force
```

如果提示「正在使用中」，先停设备：

```powershell
Get-PnpDevice | Where-Object { $_.FriendlyName -like '*A-Volute*' } | Disable-PnpDevice -Confirm:$false
pnputil /delete-driver oem42.inf /uninstall /force
```

### 端点属性清不掉

```powershell
# 停音频服务后手动清
Stop-Service Audiosrv -Force

$MM = 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Render'
Get-ChildItem $MM | ForEach-Object {
    $pk = Join-Path $_.PSPath 'Properties'
    if (Test-Path $pk) {
        Remove-ItemProperty $pk -Name '{f363df17-a750-4ac3-b7b5-2bbeffa9085f},11' -ErrorAction SilentlyContinue
    }
}

Start-Service Audiosrv
```

## 四、进不了系统怎么办

这是关闭测试签名或驱动签名冲突时最坏的情况。

### 方法 1：进恢复环境禁用签名强制

1. 开机后**连续强制关机 3 次**（按住电源键 5 秒），第 4 次会自动进入恢复环境
2. 疑难解答 → 高级选项 → 启动设置 → 重启
3. 重启后按 **7** 或 **F7**，选择「禁用驱动程序签名强制」
4. 进入系统后立刻跑 `uninstall.ps1`

### 方法 2：用安装 U 盘修复

1. 用 Windows 安装 U 盘启动
2. 选择「修复计算机」→ 疑难解答 → 命令提示符
3. 找到系统盘（通常是 `D:` 而不是 `C:`）：

```cmd
diskpart
list volume
exit
```

4. 删除有问题的驱动包：

```cmd
dism /image:D:\ /get-drivers
dism /image:D:\ /remove-driver /driver:oem42.inf
```

5. 关闭测试签名（离线修改 BCD）：

```cmd
bcdedit /store D:\Boot\BCD /set {default} testsigning off
bcdedit /store D:\Boot\BCD /set {default} nointegritychecks off
```

### 方法 3：系统还原点

如果装之前建了还原点：

恢复环境 → 疑难解答 → 高级选项 → 系统还原 → 选安装前的日期

**这也是为什么建议装之前先建还原点。**

## 五、安全关闭 Secure Boot 之前的检查

关闭 Secure Boot 会影响：

- Windows 11 的某些安全功能（内存完整性 / 内核 DMA 保护可能受限）
- 双系统引导的签名校验
- 部分企业环境的设备合规检查

如果这些对你重要，装之前请评估。

重新开启 Secure Boot 之前，**必须**确认：

```powershell
# 1. 测试签名已关闭
bcdedit /enum {current} | Select-String testsigning
# 应显示 No

# 2. A-Volute 驱动包已卸载
pnputil /enum-drivers | Select-String "a-volute"
# 应无输出

# 3. 设备管理器里没有 A-Volute 组件
Get-PnpDevice | Where-Object { $_.FriendlyName -like '*A-Volute*' }
# 应无输出
```

三项都确认后才能进 BIOS 开 Secure Boot，否则会进不了系统。

## 六、备份建议

装之前做这两件事，成本极低：

### 1. 建系统还原点

```powershell
Checkpoint-Computer -Description "Before Nahimic Port" -RestorePointType MODIFY_SETTINGS
```

### 2. 记录当前音频栈状态

```powershell
.\scripts\diagnose\dump-apo.ps1 | Out-File "$env:USERPROFILE\Desktop\apo-before.txt"
.\scripts\diagnose\check-env.ps1 | Out-File "$env:USERPROFILE\Desktop\env-before.txt"
```

出问题时能对比出到底改了什么。

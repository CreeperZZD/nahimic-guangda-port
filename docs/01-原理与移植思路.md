# 01 · 原理与移植思路

本文说明 Nahimic 3 在整个音频栈中的位置、它如何做设备识别，以及为什么"同一模具、改一行硬件 ID"就能完成移植。

---

## 1. Nahimic 在音频栈里的位置

Windows 的音频处理链（自下而上）：

```
应用（游戏 / 播放器）
    │  写入共享音频会话
    ▼
Windows 音频引擎 (AudioEngine, 跑在 audiodg.exe)
    │  按端点声明的格式混音、重采样
    ▼
┌─────────────────────────────────────┐
│  端点 APO 链（Audio Processing Object）│
│    SFX  →  MFX  →  EFX              │
│    流效果    模式效果   端点效果        │
└─────────────────────────────────────┘
    │
    ▼
音频驱动（Realtek ALC256，走 Intel Smart Sound）
    │
    ▼
物理 DAC → 扬声器 / 耳机孔
```

**APO 就是"插件"。** Windows 允许在端点上挂三段 APO，每段通过注册表键声明用哪个 COM 类：

| 注册表键（`FxProperties` 下） | 含义 |
|---|---|
| `{d04e05a6-594b-4fb6-a80d-01af5eed7d1d},5` | SFX（流效果，最靠近应用） |
| `{d04e05a6-594b-4fb6-a80d-01af5eed7d1d},6` | MFX（模式效果） |
| `{d04e05a6-594b-4fb6-a80d-01af5eed7d1d},7` | EFX（端点效果，最靠近硬件） |
| `...,13` / `...,14` / `...,15` | 三段"复合链"写法（可放多个 CLSID） |

Nahimic 的核心就是这三个槽位里的 `NahimicAPO4.dll`（CLSID `{670173E3}` / `{670173E4}` / `{670173E5}`）。

---

## 2. 三个组成部分

完整的 Nahimic 3 套件由三块拼起来：

### ① SWC 软件组件驱动（`A-VoluteNhApo4Swc.inf`）

- 匹配设备：`SWC\VEN_AVOL&AID_0002` ~ `AID_1F02`（34 个产品变体）
- 作用：
  - 把 `NahimicAPO4.dll`、`NahimicAPO4API.dll`、`NahimicService.exe`、`NahimicSvc32/64.exe` 等复制到 `System32`
  - 注册 4 个 APO COM 类（SFX / MFX / MFX-Capture / EFX）
  - 创建 `NahimicService` 服务
  - 写 `HKLM\SOFTWARE\Nahimic\ProductCohabitation=2`

**这一块原样安装，签名有效，不需要任何修改。**

### ② EXT 扩展驱动（`AVoluteNH3Ext.inf`）—— 移植的关键

它挂在**编解码器设备**（ALC256）上，做三件事：

1. **创建 SWC 子设备**
   ```
   [RtkHDARenderCapture0_Install.Components]
   AddComponent = AVOLUTE_NH4APO,,APO_Install

   [APO_Install]
   ComponentIDs = VEN_AVOL&AID_0F02
   Description = "A-Volute Nh4 Audio Effects Component"
   ```
   没有这一步，上面 ① 的驱动永远不会被绑定。

2. **写 `HKR,Settings,EPSubVer2=4`**
   通知 Realtek 驱动栈切换到 "SWC APO4" 端点模式，让 APO 真正进链。

3. **往各音频拓扑追加接口属性**
   ```
   PKEY_PRODUCTID   = "A-Volute.Nahimic"
   PKEY_VENDORNAME  = "Thunderobot"
   ```
   这是 **Nahimic 应用识别"设备存在"的唯一依据**。

它的硬件匹配表长这样（节选）：

```ini
[DeviceExtensions.NTamd64.10.0...15063]
%Device.ExtensionDesc% = RtkHDARenderCapture0_Install,INTELAUDIO\FUNC_01&VEN_10EC&DEV_0255&SUBSYS_152D1331 ;; NLZ
%Device.ExtensionDesc% = RtkHDARenderCapture0_Install,INTELAUDIO\FUNC_01&VEN_10EC&DEV_0256&SUBSYS_152D1535 ;; NLY ★雷神猎刃16
%Device.ExtensionDesc% = RtkHDARenderCapture0_Install,INTELAUDIO\FUNC_01&VEN_10EC&DEV_0269&SUBSYS_1EC91A02 ;; A1
```

**白名单以外一律不绑定。** 这就是官方 RestoreTool 会拒绝装在别的机型上的唯一原因（它的 `PreInstall.ps1` 会先对照本机设备做校验）。

### ③ 应用层（`*.appxbundle`）

Nahimic 3 是一个 .NET Native UWP 应用，含自定义能力 `AVolute.audioDevices`。它 **没有任何硬件锁定**——启动后只做一件事：读端点的 `PKEY_PRODUCTID`，等于 `A-Volute.Nahimic` 就认为设备可用。

**所以应用层完全不用改。**

## 3. 为什么"改一行"就能移植

同模具机型的硬件差异往往只是 **子系统 ID 的末几位**：

| 机型 | 编解码器 | 实例 ID 片段 |
|---|---|---|
| 雷神 猎刃 16 | ALC256 | `DEV_0256&SUBSYS_152D1535` |
| 七彩虹 隐星 G16 24 | ALC256 | `DEV_0256&SUBSYS_152D1534` |

`0x152D` 是广达（Quanta）的 PCI 厂商号 —— 两台机器是同一套模具方案的不同品牌贴牌，喇叭、拓扑、走线完全一致，只有 OEM 编号差一位。

因此只要在 EXT INF 的匹配表里补一行：

```ini
%Device.ExtensionDesc% = RtkHDARenderCapture0_Install,INTELAUDIO\FUNC_01&VEN_10EC&DEV_0256&SUBSYS_152D1534
```

整条链路就通了：

```
补一行匹配 → EXT 绑定到本机 ALC256
    → 创建 SWC 子设备 → SWC 驱动装上 → APO/服务文件落地
    → 写 EPSubVer2=4 与端点属性 → APO 进链
    → 应用读到 PKEY_PRODUCTID → 识别成功
```

`scripts/prepare-kit.ps1` 做的就是这个（并且会读出你机器的真实 SUBSYS 值，不需要你手改）。

## 4. 为什么必须开测试签名

INF 文件不是孤立的，它有一个配套的 `.cat` 目录文件，里面是**对该 INF 数字签名的哈希**。

改了 INF 的任何一个字节 → 哈希对不上 → 签名失效 → Secure Boot / 驱动签名强制会拒绝装载。

因此：

- 必须 `bcdedit /set testsigning on`
- 必须关 Secure Boot（Secure Boot 开启时测试签名模式无法生效）
- 副作用：桌面右下角出现「测试模式」水印，且无法去除

> 这和社区长期维护的 MSI 版 Nahimic 移植驱动（NotebookTalk 等项目）走的是同一条路，不是本项目独创的野路子。

**注意：我们不修改 `.cat`，也不伪造签名。** 只是让系统在测试模式下接受"签名过的 INF 被本地修改"这个事实。

## 5. 调音档案（NH3ProductSettings.cab）

这个 CAB 里是 25 个 XML 格式的 `.nsx` 文件，按 `<子系统ID>_<设备类型>.nsx` 命名：

```
152D1535_InternalSpeakers.nsx    ← 猎刃 16 内置喇叭调音
152D1535_Headphone.nsx
152D1535_ExternalSpeakers.nsx
...（音乐/游戏/影音/通讯场景预设）
```

文件名里的子系统 ID 必须匹配本机，否则 Nahimic 找不到调音曲线，会退回默认参数（**功能正常，只是听感偏"通用"**）。

`prepare-kit.ps1` 的处理方式是：把 `152D1535_*.nsx` 复制一份改名为 `<你的SUBSYS>_*.nsx`，然后重新打包 CAB。同模具同喇叭单元，曲线通用。

CAB 重建失败也无所谓——用 `-SkipCab` 跳过即可，音效照常工作。

## 6. 移植流程总览

```
check-env.ps1          判断本机是否满足条件（只读）
      │
      ▼
prepare-kit.ps1        读本机硬件 ID → 改写匹配表 → （可选）重建调音 CAB
      │                原目录只读，输出到 kit-ready
      ▼
install.ps1 第 1 段    开测试签名 → 重启
      │
      ▼
install.ps1 第 2 段    装 SWC → 装 EXT → 等组件 → 设权限 → 装应用 → 重启
      │
      ▼
dump-apo.ps1           验证端点 APO 链是否挂上
radar-probe.ps1        验证声音追踪器是否输出方位（可选）
```

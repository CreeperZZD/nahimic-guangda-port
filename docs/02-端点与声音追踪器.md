# 02 · 端点与声音追踪器

> 这份文档回答一个被反复问到的问题：**为什么音效都正常，声音追踪器却只有前方？**
>
> 结论先行：**这是音频端点的能力限制，不是安装失败。** 换 USB 声卡或改用内置扬声器即可恢复 360°，改注册表、换驱动、开测试签名都解决不了。

---

## 1. 声音追踪器到底是什么

Nahimic 的 Sound Tracker 会在屏幕上画一个雷达，把游戏里的声源方向实时标出来。

它的工作方式是**在 APO 内部做方位分析**：拿到多声道（或可上混的）音频流，用 HRTF / 声道能量分布推算出每个声源在水平面上的角度，然后写进注册表供 App 读取：

```
HKLM\SOFTWARE\Nahimic\A-Volute.Nahimic\{703F89B6-57E8-4B2D-A4C1-F56E236D64FA}
  └─ {752EDE94-01E3-4298-9FA5-4A4F89A738E0}
       {0CA8E8B0-4D8A-11E5-99F9-50E549C4ED27}, 0   ~ , 23     ← 24 个值
```

**数据结构（重要，容易踩坑）：**

每个值是 **8 字节**，不是 4 字节：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | float32 | 该方向的当前电平 |
| 4 | float32 | 该方向的峰值 |

24 个方向 × 8 字节。**如果按 4 字节 / double 解析，会得到全 0 或者垃圾值。**

`scripts/diagnose/radar-probe.ps1` 用的是正确的解析方式。

---

## 2. 实测数据：三种端点，两种结果

测试机型：七彩虹 隐星 G16 24 + Windows 11 + Realtek 6.0.9622.1。
判定方式：播放真实内容（游戏 / App 自带「体验」），读雷达注册表的最大方向数。

| # | 端点 | 端点格式 | APO 链形态 | 雷达 |
|---|---|---|:---:|---|
| A | 内置扬声器（Realtek） | **6 ch** / 48k / 16bit | 复合链 `,5` `,6` + `,13/14/15` | ✅ **360°（最多 7 个方向同时有能量）** |
| B | USB 小尾巴（CX31988 + 97220） | 2 ch / 48k / 32bit | **单层三段** `,5` `,6` `,7`，无 `,13/14/15` | ✅ **360°** |
| C | 主板耳机孔（Realtek） | 2 ch / 48k / 32bit | 复合链 `,5` `,6` + `,13/14/15` | ❌ **只有前方左右** |

### 提炼出的规律

把三行摆在一起，失败的组合只有一种：

| 组合 | 结果 |
|---|---|
| 复合链 + 6 声道 | ✅ |
| 单层三段 + 2 声道 | ✅ |
| **复合链 + 2 声道** | ❌ |

**"复合链"指的是 `,13/14/15` 这三个键里放两个 CLSID：**

```
,13 = {DA2C9ECE-7418-4906-B4FA-0A00B3EB88AA} | {670173E3-78CF-11E5-A837-0800200C9A66}
        ↑ 包装层（OEM 通用 APO）              ↑ 真正的 Nahimic SFX
,14 = {A296D363-...} | {670173E4-...}
,15 = {A29EB043-...} | {670173E5-...}
```

推断：**包装层 APO 在多声道端点上才能正常做方位解析**。它拿到 2 声道流时，会把方位分析降级成"左/右"两档，于是雷达只剩前方。

而 USB 声卡上 Nahimic 用的是最朴素的单层挂法（三个槽各放一个 CLSID），不需要包装层，2 声道也能工作。

## 3. 为什么主板耳机孔无法变成多声道

有人会想：那把耳机孔端点改成 6/8 声道不就行了？

**试过了，做不到。** 三层阻碍：

### 3.1 端点没有声明多声道

```
PKEY_AudioEndpoint_PhysicalSpeakers = 0x3        ← 只声明 FL|FR（立体声）
PKEY_AudioEndpoint_FullRangeSpeakers = 0x3F      ← 但全频段写了 6 声道位掩码
```

这两个值互相矛盾。Windows 声音设置的「配置」按钮，只有在驱动**声明支持 5.1/7.1** 时才出现。你这台机器没声明，所以那个按钮是灰的或根本不存在 —— 这就是为什么"别人的机器能点配置、我的点不开"。

### 3.2 驱动直接拒绝

用官方接口 `IPolicyConfig::SetDeviceFormat` 尝试设置 6 声道 / 8 声道格式：

```
8ch/48k/32f   -> 0x88890008  AUDCLNT_E_UNSUPPORTED_FORMAT
8ch/48k/16    -> 0x88890008
6ch/48k/32f   -> 0x88890008
6ch/48k/16    -> 0x88890008
```

**全部被驱动拒绝。** 这是驱动层的硬限制，不是权限或注册表问题。

### 3.3 绕过驱动改注册表会被还原

直接修改 `MMDevices\...\{e4870e26-...},0`（端点设备格式）为 6 声道，即使停止 `Audiosrv` 后写入成功，服务一启动就会被 Realtek 驱动重建回 2 声道。

所以这条路是**物理性走不通**的，不用再试。

---

## 4. 那"别人的双声道为什么能 360"

因为他们机器的端点**声明了多声道**（走的是上面表格 A 或 B 的情形之一）：

- 有些机型 Realtek 驱动声明了 5.1，端点虽然物理只有两个喇叭，但送进去的流是 6 声道 → 情形 A
- 有些人用 USB 声卡 / 游戏耳机 → 情形 B

本质上都不是"双声道能算方位"，而是**端点声明了多声道**。物理喇叭数量不影响雷达，声明才影响。

---

## 5. 解决方案

### 推荐：用 USB 声卡 / 小尾巴

插上即用，无需任何配置。2 声道端点上 Nahimic 走单层链，方位分析正常。

实测：CX31988 + 97220 方案的小尾巴，雷达 360° 正常，音效也正常。

### 备选：用内置扬声器

内置扬声器端点是 6 声道（`Alc256` 的 `rearlineout` 拓扑），雷达正常。

适合不外接设备的情形。缺点是不能戴耳机。

### 不推荐：继续折腾主板耳机孔

以下方法**我们都试过，全部无效**，不用再花时间：

| 尝试 | 结果 |
|---|---|
| 用 `IPolicyConfig::SetDeviceFormat` 设 6/8 声道 | ❌ 驱动返回 `0x88890008` |
| 直接改注册表端点格式为 8 声道 | ❌ 服务启动后被还原成 2 声道 |
| 把 Nahimic APO 挂到 8 声道虚拟声卡（SteelSeries Sonar） | ❌ APO 加载了但方向数 0 |
| 把 Nahimic 挂到 Razer 7.1 虚拟声卡 | ⚠️ 能出方位但虚拟卡不出声（其 APO 走私有共享环） |
| 只把 Nahimic 放在 EFX 槽（最后一环） | ❌ 有声，方向数只有 1~2 |
| 把复合链换成单层三段链（模仿 USB 声卡） | ❌ 有声，方向数 0 |
| 把扬声器的完整配置（含复合链）复制到耳机孔 | ❌ 音效通了，雷达仍只有前方 |
| 自建 WASAPI loopback 桥接（8ch 采集 → 降混 2ch） | ❌ 雷蛇虚拟端点 loopback 不产数据 |

**核心原因**：Nahimic 的方位分析绑定在 SFX 段，而主板耳机孔的 SFX 段在 2 声道端点上必然降级。任何注册表层面的改写都无法突破驱动对格式的限制。

## 6. 相关诊断命令

```powershell
# 看每个端点的声道、APO 链形态、雷达预测
.\scripts\diagnose\dump-apo.ps1

# 实时看雷达方向数（需先开 Nahimic 的「体验」或进游戏）
.\scripts\diagnose\radar-probe.ps1 -Count 30
```

`dump-apo.ps1` 会直接告诉你：

```
Nahimic SFX/MFX 已挂 + 端点 6ch/8ch           -> 音效正常，雷达期待 360
Nahimic SFX/MFX 已挂 + 端点 2ch + 单层三段链  -> 音效正常，雷达期待 360
Nahimic SFX/MFX 已挂 + 端点 2ch + 复合链      -> 音效正常，雷达只有前方
没有 Nahimic 键                              -> 音效不生效，需重装或检查驱动
```

---

## 7. 一句话总结

> 音效（EQ / 降噪 / 预设）和雷达是**两件独立的事**。
> 音效看 APO 有没有挂上，雷达看端点的声道声明。
> 前者能靠移植解决，后者只能靠换设备解决。
